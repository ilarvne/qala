# Privacy, evidence and safety

This document describes the prototype's data choices and release limits. It is a product and engineering record, not a legal-compliance certification.

## Data flow

| Data | Purpose | Storage and disclosure |
|---|---|---|
| Chosen landmark or one-time current coordinates | Rank nearby places | Transient planner processing. Precise coordinates are not persisted in preference memory or browser local storage. A new starting point also changes the route coordinates disclosed below. |
| Selected route coordinates and instruction language | Obtain pedestrian street geometry and directions | The backend sends these to the configurable Valhalla service, by default `https://valhalla1.openstreetmap.de`. This happens when the interface requests the current plan's street route, before directions start. No user identity, request text, session capability or preference ID is sent. A bounded in-memory route cache has a five-minute lifetime and no disk persistence. The provider's own logs and retention are outside this cache. |
| Opt-in live GPS fixes | Show current position and advance the current route's instructions | Browser-tab state only. Live fixes are not sent to the planner or routing service, stored in preference memory, or written to browser local storage. This does not automatically recalculate the route. |
| Map view and tile requests | Display the city map | The browser requests OpenFreeMap styles, vector tiles, fonts and sprites for the embedded MapLibre 2D/3D map. No provider key is required. Providers can observe network requests and viewed areas, including areas shown while following GPS. Map requests do not include planner text or session capabilities. Provider retention is separate from local preference storage. |
| Fixed Astana city coordinates and requested forecast window | Consider weather when choosing places | Open-Meteo receives a fixed city coordinate, not the user's precise location, raw request or session ID. Forecasts have a 15-minute in-memory cache. Source details expose the forecast interval, fetch time and attribution. A city forecast does not verify conditions on a particular street. |
| Official event calendar | Return dated event discovery results | The server fetches public operator calendar metadata with a robots check and a one-hour in-memory cache. User messages, exact location and capabilities are not sent to the operator. Only published titles, dates and URLs are used; unavailable venue, time and tickets remain unknown. |
| Request text and filters | Infer intent and enforce constraints | Transient planner input and current client conversation branch. The running local MiniLM embedding model processes queries without runtime model-network calls; explicit prewarming downloads weights once. The portable hash mode is also local. The enabled AlemPlus language model receives canonical preferences and selected public POI evidence to select validated presentation enums, without raw messages, session capabilities or precise user coordinates. AlemPlus reranking receives bounded public POI text and canonical interests. Optional OpenAI embeddings send public POI text and the search query to that provider. |
| Opt-in preferences | Avoid repeating interests and settings | SQLite stores a SHA-256 session digest, allowlisted interests, language, duration, indoor/accessibility settings, category exclusions, walking budget and a coarse location rounded to two decimal places. Expiry is 30 days and is enforced during memory operations. Raw messages are not retained. |
| Browser saved places and session capability | Keep selections and access preferences | Explicitly saved public place records use local storage, including their source facts and displayed visit suggestions. A temporary opaque session capability uses tab storage; it is persisted across visits only after explicit preference consent. Forget removes the persistent capability and immediately disables memory reads and writes, including across open tabs. The capability is a bearer secret. |
| Spoken request and output | Optional voice interaction | Browser/provider permissions apply. ElevenLabs receives synthesized text or conversation audio, selected starting-point coordinates and current filters. The EN/RU/KK voice dialog discloses this before Start. The application does not deliberately retain raw audio. Provider retention requires separate configuration. |
| Explicit dictation recording | Convert speech into a planner request | Only after Start: the browser records a bounded clip and sends it with the selected language to AlemPlus. Kazakh uses its dedicated recognition model. The server caps uploads at 8 MiB, sends no-store responses and does not persist recordings or transcripts. Closing/cancelling releases microphone tracks and discards the pending result. Provider retention remains separate. |
| Telephone call | Optional incoming voice channel | The telephony provider handles call metadata and speech processing. Recording should remain off unless a separate, explicit notice and consent flow is implemented. |
| Public POI records | Recommendation evidence | Versioned dataset with sources, identifiers, collection dates and attribution. No user location enters this dataset. |

Rounding coordinates to two decimal places is coarse location, not anonymity. Do not store a child's home, school or travel history as a preference. A session digest is pseudonymous, not anonymous. Logs, reverse proxies and hosting platforms may still process IP addresses and request metadata. Production logging must redact payloads, phone numbers and session capabilities.

## User control

Location permission follows an explicit action and can be refused. Choosing current location performs a one-time position lookup and uses that coordinate as planner input. Following a route requires a separate opt-in action. Turning following off, ending navigation, replacing the plan, changing planning context, a geolocation error or unmounting the application clears the active browser location watcher. Synthetic browser checks cover timeout, retry and end-navigation cleanup; actual-device location accuracy and walking behavior have not been verified.

A sample landmark allows testing without GPS. Memory starts disabled on a new visit; a previously opted-in browser can restore its saved controls. Users can inspect, edit or delete remembered preferences. Atomic consent generations prevent an older pending request or queued edit from recreating a record after deletion. Stale explicit writes return a conflict and are not retried automatically. The client stops reading or writing preferences immediately when consent is revoked, even if the deletion request fails; it exposes the failure so deletion can be retried. A newly consented request can save again. A missing permission or voice-provider key leaves the text experience usable. Sample landmarks are labeled.

The configured ElevenLabs agent requires private signed sessions, disables voice recording and requests zero-day retention with transcript/audio deletion in provider settings. This is configured behavior, not an independent audit of provider infrastructure. Its HTTPS tunnel forwards only the authenticated planner webhook; it exposes no chat, memory, documentation or general application routes. The local browser app remains on its existing port. A quick tunnel has a temporary address and must remain running for the provider tool to work.

## Grounding and unknown fields

Retrieved POI records are evidence, not instructions. The optional model can select only approved evidence and activity enums, with exact source IDs and category compatibility checked. Arbitrary provider-authored prose never enters the response. The application renders localized facts and approved activity templates. Source links let users inspect evidence. Activities such as taking a photo remain suggestions. Walking duration is an estimate. Weekly schedules do not confirm tickets, queues, exceptional closures or availability today.

OpenUI renders a bounded component vocabulary after plan validation. Its place actions resolve only IDs in the trusted response. Arbitrary HTML, query/mutation components and browser tool execution are not enabled. Source photographs retain their author, licence and original URL. The one imported Mangrove rating has a verified signature and exact OSM identity match; this proves record integrity, not a verified customer visit. It has no textual opinion. Missing ratings and reviews remain unknown.

Unknown opening hours must appear as unknown. Known closures exclude a venue when the plan needs entry. Unknown sockets require checking with staff. Accessibility requires explicit evidence before a strict accessible filter can include a place. A ramp icon, descriptive text or broad category does not prove accessible entrances, toilets or the full walking route. Provider landmark models are visual orientation aids, not verified entrance, accessibility or survey evidence.

## Physical context

For evening requests, favor public and well documented places. Never recommend trespassing, roofs, restricted areas, abandoned sites or following strangers. Do not invent safety guarantees. Wind, ice, construction, crossings and queues can invalidate walking-time estimates even when a route follows mapped streets. The current interface uses Valhalla pedestrian geometry and instructions, validates the provider response and rechecks the time budget. It exposes routing failures and endpoint-snap warnings. Mapped paths do not verify public entrances, temporary closures, safe crossings or step-free access. Users should check local conditions. Kazakh turn instructions currently fall back to English with a warning; several redesigned controls also remain English.

A request shortly before a flight requires an explicit airport-transfer estimate and deducts it together with a 90-minute reserve for airport formalities. When the transfer estimate is missing, the planner asks for it and offers no excursion. The prototype does not know the passenger's airline rules, baggage status, live road traffic or gate closure. A conservative stay-nearby response is preferable to an itinerary that consumes all available time. The transfer input is user-supplied, not a live traffic measurement.

## Technical abuse controls

Treat prompt-like text in a POI description as untrusted. Test requests that demand ignoring filters, revealing keys, or inventing a place. Validate input lengths, geographic ranges, language codes and session identifiers. Keep private model, voice and telephony credentials server-side. Verify telephony signatures for exposed webhooks. Use deployment authentication, rate limits, payload limits and restricted CORS before opening a public service.

The local prototype's tests are evidence for specific implemented behavior. They do not establish penetration-test coverage. Production rollout needs an independent security review, data-retention review and load testing.

## Source and legal review

OpenStreetMap data requires attribution and applicable licence handling. Generated art is labeled illustrative. Review provider terms before redistributing proprietary venue text or map tiles. For production in Kazakhstan, review applicable personal-data, localization, consumer and telecommunication requirements with qualified local advice.

Design reference: [ICO guidance on geolocation](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/childrens-information/childrens-code-guidance-and-resources/age-appropriate-design-a-code-of-practice-for-online-services/10-geolocation/). We use its principles of granularity, visible use and protective defaults as design guidance. We do not assert that this UK guidance determines Kazakhstan law.
