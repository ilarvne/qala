# Ключи для источников мест

Предоставленный пользователем ключ **2GIS Places API** подключён на сервере и проверен реальными запросами 20 октября 2026 года. Он используется в окне источников места. Ключи не нужны текущей встроенной карте MapLibre/OpenFreeMap. Google остаётся необязательным отдельным источником: его ключ в текущем окружении не настроен.

## Google

1. В Google Cloud создать или выбрать проект и подключить billing.
2. Включить **Places API (New)** — `places.googleapis.com`.
3. Создать серверный ключ, ограниченный этим API. При ограничении по IP нужен исходящий публичный IP сервера; браузерное HTTP-referrer ограничение не подходит серверному HTTP-запросу.
4. Записать `GOOGLE_PLACES_API_KEY` в локальный `.env` либо передать через окружение процесса. Не использовать префикс `VITE_`: секрет остаётся на сервере.

Официальная [инструкция Google](https://developers.google.com/maps/documentation/places/web-service/get-api-key). Наличие ключа не означает успешной авторизации: API должен быть включён, billing активен, ограничения совместимы с запросом.

В проекте есть ограниченная проверка:

```bash
# Только наличие конфигурации, без сетевого запроса и расходов.
.venv/bin/python scripts/probe_map_api_access.py --provider google

# Один запрос Text Search, максимум одно место; тариф провайдера применяется.
.venv/bin/python scripts/probe_map_api_access.py --provider google --live

# Дополнительно запросить доступную выборку отзывов.
.venv/bin/python scripts/probe_map_api_access.py --provider google --live --reviews
```

Запрос использует точный FieldMask, без `*`. Рейтинг и число оценок относятся к Text Search Enterprise; добавление отзывов — Enterprise + Atmosphere. Это уровни запрашиваемых полей, не обещание бесплатного использования. [Документация Text Search](https://developers.google.com/maps/documentation/places/web-service/text-search).

Проверка сообщает доступность полей, количество найденных ресурсов и Google Place ID. Тексты отзывов, имена фото-ресурсов, изображения, полный ответ и ключ не сохраняются. HTTP 401/403/429 или перенаправление завершают запрос без повторения. Это проверка доступа, а не подключённый городской импорт или оценка полноты покрытия.

Google возвращает ограниченную выборку: объект Place содержит до пяти отзывов, а фото-ответы — до десяти фотографий. Имена фото-ресурсов могут истекать; [Place Photos](https://developers.google.com/maps/documentation/places/web-service/place-photos) требует получать актуальные имена и сохранять обязательную атрибуцию при показе. [Правила Places](https://developers.google.com/maps/documentation/places/web-service/policies) отдельно регулируют хранение, отображение на карте и показ без карты. Ключ не делает эту информацию открытой базой для архивирования и не меняет выбранный рендерер Qala.

## 2GIS — подключённый источник

Нужен ключ **Places/Search API для HTTP-запросов**, с переменной `TWOGIS_API_KEY`. Ключ, ограниченный мобильным SDK/App ID, не подходит этому запросу. [Platform Manager и создание ключа](https://docs.2gis.com/en/platform-manager/subscription/keys) описывают месячный демодоступ и ключи подписки.

```bash
.venv/bin/python scripts/probe_map_api_access.py --provider 2gis
.venv/bin/python scripts/probe_map_api_access.py --provider 2gis --live
```

Второй вариант делает ровно один запрос. Проверяется и HTTP-код, и `meta.code`: HTTP 200 с `meta.code=400` не считается успешным доступом. Состав статистики зависит от выданного доступа; тексты отзывов и фотографии этим пробником не обещаются. Значения ключа нет в отчёте или тексте исключения, хотя протокол 2GIS передаёт его в query-параметре запроса.

В приложении `GET /api/pois/{poi_id}/sources/2gis?language=ru` запрашивает данные только после открытия окна источников конкретного места. Доступны также `en` и `kk`. Сервер отправляет название и координаты публичного POI; переписка и текущая точная локация пользователя в этот запрос не входят. Ключ отсутствует в клиентской сборке, ответах и диагностике.

Для Байтерека и Национального музея проверены известные идентификаторы с привязкой к исходному местному POI. Остальные совпадения требуют точного имени или алиаса и расстояния до 200 м; несколько подходящих филиалов не сливаются. Известные закрытые объекты не вызывают запрос к провайдеру. Отдельный источник не переименовывает POI и не подменяет открытые данные.

Наблюдаемые `general_rating`, `general_review_count_with_stars` и `general_review_count` показаны раздельно. Другие `org_*` значения не усредняются с ними и не заполняют пропуски. Реальные ответы также содержали недельный график и комментарии к кассам и перерывам. Признак `flags.photos` означает наличие фото у провайдера, а не полученные фотографии. Этот доступ не выдал сами изображения, тексты отзывов или контакты проверенных двух мест. Кнопки фото и отзывов ведут к соответствующей организации; существующая лицензированная галерея Qala сохраняется.

Завершённые ответы 2GIS не кэшируются и не попадают в JSON/CSV/GeoJSON корпуса, векторный индекс или память предпочтений. Одновременные одинаковые запросы используют одну выполняющуюся операцию. Ответ HTTP имеет `Cache-Control: no-store`; запросы ограничены по частоте, длительности, размеру ответа и бюджету процесса. HTTP 401/403/429 приостанавливает дальнейшие обращения этого процесса вместо повторов. Условия конкретной подписки задают разрешённый объём использования; успешный тест ключа не доказывает доступность всех полей или всего города.

## Яндекс и остальные ключи

Обычный [Яндекс Places API](https://yandex.com/maps-api/docs/geosearch-api/response.html) не обещает выдачу рейтингов, фотографий и текстов отзывов. Покупка этого ключа сама по себе не решает текущий пробел в медиа. Возможность официального виджета отзывов рассматривается отдельно от экспорта данных.

Ранее настроенные AlemPlus и ElevenLabs обслуживают агента, распознавание и речь; они не авторизуют Google, 2GIS или Яндекс. Foursquare требует отдельной проверки реального покрытия Астаны и условий выбранного продукта до покупки доступа.

Пробник отдаёт приоритет переменной окружения, затем `.env`; явно пустая переменная окружения отключает соответствующий секрет. Конфигурация не вызывает платных запросов при старте приложения. Официальные API и публичные сайты имеют отдельные состояния доступа: отсутствие авторизации API не считается CAPTCHA публичной карты, а блокировка сайта не снимается заменой домена или браузерной сессии.
