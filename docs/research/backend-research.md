# Backend architecture research · 19 October 2026

Exa workstreams returned 30 candidate sources across framework persistence, POI provenance, pedestrian routing and speech/telephony. Primary documentation was fetched to resolve API details; candidate count is discovery coverage, not a claim that every page was read in full. Context7 independently checked the current LangChain vector-store API. The attached hackathon brief was read before design.

| Decision | Evidence and implication |
| --- | --- |
| A bounded LangGraph planner with conditional abstention | [Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api) documents state, nodes, normal/conditional edges and graph compilation. This supports context → retrieval → route budget → grounded answer without an uncontrolled tool loop. |
| Bounded LLM presentation selectors, trusted rendering | Source matching establishes attribution but cannot prove arbitrary generated prose. The implemented model boundary accepts only strict enums for evidence focus, introduction style and category-bound action kind. Every response sentence is locally rendered; model-authored prices, unsafe actions and other free text cannot be promoted. Valid selections are labeled `llm-assisted`, not unrestricted generation. |
| Minimized preference memory separate from full graph state | [Persistence](https://docs.langchain.com/oss/python/langgraph/persistence) distinguishes thread checkpoints from application stores; [checkpointers](https://docs.langchain.com/oss/python/langgraph/checkpointers) save graph state at super-step boundaries. Saving full state would retain exact locations, so the shipped graph stays transient and SQLite stores only explicit opt-in coarse preferences. |
| Real source snapshot with repeatable collection | [Overpass language guide](https://wiki.openstreetmap.org/wiki/Overpass_API/Language_Guide) documents metadata output and bounding-box centers. A center is not guaranteed to be inside an area; entrance/route uncertainty must be visible. [OSM copyright](https://www.openstreetmap.org/copyright) establishes attribution and ODbL terms. |
| Hybrid lexical/vector/geo retrieval with honest local representation | [LangChain InMemoryVectorStore](https://reference.langchain.com/python/langchain-core/vectorstores/in_memory/InMemoryVectorStore) supports source-backed Documents, custom Embeddings and cosine-scored retrieval. Offline feature hashing is lexical rather than neural semantics. Actual neural OpenAI embeddings are an explicit configured option. Metadata constraints and route time remain authoritative regardless of similarity. |
| Approximate pedestrian links by default | [OSRM API](https://project-osrm.org/docs/v5.24.0/api/) and [profiles](https://project-osrm.org/docs/v26.6.1/profiles) explain that transport mode is fixed when OSM data is extracted, not changed by renaming the URL path. Therefore a driving response must never be presented as walking. The shipped fallback clearly reports approximate point links with a detour factor and conservative pace. A verified foot-routing service is future integration work. |
| Browser private-agent authentication through backend | [Signed URL endpoint](https://elevenlabs.io/docs/eleven-agents/api-reference/conversations/get-signed-url) is GET `/v1/convai/conversation/get-signed-url?agent_id=...`; [agent authentication](https://elevenlabs.io/docs/eleven-agents/customization/authentication) describes temporary URLs and server-side API keys. No browser credential exposure. |
| Use an actual Kazakh-capable speech model | [ElevenLabs model support](https://elevenlabs.io/docs/overview/models) lists Kazakh for Eleven v3, whereas multilingual_v2 lists 29 languages without Kazakh. Shipped TTS defaults to `eleven_v3`; configured provider behavior remains subject to live testing. |
| Native phone/SIP configuration plus secure advanced webhook | [Native Twilio integration](https://elevenlabs.io/docs/agents-platform/phone-numbers/twilio-integration) is the simpler primary setup; [register-call](https://elevenlabs.io/docs/agents-platform/phone-numbers/twilio-integration/register-call) is for existing custom call control. The exact REST endpoint is POST `/v1/convai/twilio/register-call`; the response is TwiML, and μ-law 8000 Hz is required. [Twilio security](https://www.twilio.com/docs/usage/security) requires signature validation using the original public URL and submitted parameters. |
| Venue source overrides generic missing hours | [National Museum](https://www.nmrk.kz/en/) lists Tuesday–Sunday 10:00–18:00 and Monday off. [Baiterek operator](https://a-vm.kz/en/objects/bayterek/) lists 10:00–22:00 for June–August and 10:00–21:00 otherwise. The collection pipeline fetches both, checks expected facts, stores HTML and attaches separate operator sources. No live event claims are inferred from their news pages. |

The implementation was chosen for the judging order: useful nearby results, strict budget/context handling, concise reasons, visible uncertainty and a working demo without credentials. Production extensions are a verified pedestrian/accessibility graph, neural multilingual semantic embeddings, account-scoped storage and live venue/event feeds. These are described as extensions, not claimed as working integrations.

Verification and setup are in [backend/README.md](../../backend/README.md). Credentials were absent at initial implementation; unconfigured providers return explicit 503 responses and the source-grounded planner stays available.

Independent review also verified deletion under concurrency: a pending remembered request cannot restore a record deleted while its provider call was in flight. SQLite transactions compare a captured consent generation before writing; deletion increments a hash-only generation tombstone with 30-day expiry. New consent in a subsequent request remains possible. Schedule validation checks every occupied minute so a midday closure cannot be missed between otherwise open endpoints.
