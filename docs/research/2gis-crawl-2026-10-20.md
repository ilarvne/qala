# 2GIS: фактическая проверка карточек Астаны, 20 октября 2026

Проверены настоящие публичные карточки и текущая документация. Прямой HTTP дал две содержательные страницы, а обычный Chromium при открытии карточки музея получил CAPTCHA. После этого расширение обхода карточек остановлено. Никаких новых запросов карточек через другой User-Agent, прокси, скрытые токены или обход проверки не выполнялось. Данные ниже — исследовательские наблюдения, не импорт в открытый каталог Qala.

## Что удалось получить

| Точная карточка | Балл / 5 | Число оценок | Число текстовых отзывов во вкладке | Число фото во вкладке | Центр карты из публичного OG |
|---|---:|---:|---:|---:|---|
| [Национальный музей РК](https://2gis.kz/astana/firm/70000001018608940) | 5 | 16 270 | 2 371 | 3 692 | 51.118023, 71.469471 |
| [Монумент-Бәйтерек](https://2gis.kz/astana/firm/70000001021365759) | 4.9 | 23 213 | 3 232 | 4 176 | 51.128301, 71.430456 |

Это разные величины: число оценок не равно числу отзывов с текстом. Числа являются снимком ответа, а не гарантией неизменности. Координаты взяты из `center` публичного изображения для обмена ссылкой; они не объявлены входом или проверенным маршрутизируемым адресом. Сопоставление с существующими объектами подтверждено названием, адресом и расстоянием: музей — `osm-node-4894937300`, Байтерек — `osm-way-230401645`.

Обнаружены реальные расхождения внутри одного ответа: OG музея содержит 2 370 отзывов / 3 691 фото, а видимые вкладки — 2 371 / 3 692; OG Байтерека — 3 228 / 4 171, вкладки — 3 232 / 4 176. Парсер отдаёт видимые значения и сохраняет предупреждения. Exa также вернул индексированную `/tab/info` страницу Байтерека с 4.7 и 3 оценками, тогда как прямой ответ основной карточки показывает 4.9 и 23 213. Индексированный результат нельзя принимать за свежую карточку или безусловно сливать с ней.

В сохранённых ссылках на фото есть галерея точной карточки и публичная обложка, чей путь содержит её точный ID: `/main/branch/68/<firm_id>/common`. Это ссылки для исследования. Изображения не загружались и не добавлялись в приложение. Произвольные изображения из HTML не присваивались месту: они могут относиться к рекламе, соседним организациям или авторам. Тексты отзывов, имена авторов, приватное состояние приложения и токены не извлекались.

## Воспроизводимые свидетельства

- `artifacts/provider-crawl/2gis/records.json`: две нормализованные записи; `import_policy=evaluation_only`.
- `artifacts/provider-crawl/2gis/http-evidence.json`: URL, время, HTTP-код, размер и SHA-256 каждого исходного ответа, отдельно код ошибки внутри JSON API.
- `artifacts/provider-crawl/2gis/robots.txt`: полученные правила. `/astana/firm/...` не запрещён общим `User-agent: *`; это не лицензия на повторное использование базы.
- `artifacts/provider-crawl/2gis/browser-access.json` и `browser-challenge.png`: наблюдённый переход на `captcha.2gis.ru`, без взаимодействия с проверкой.
- `artifacts/provider-crawl/2gis/search-discovery.json`: 30 результатов Exa, 29 уникальных URL. Ещё две попытки с суммарно 15 запрошенными результатами отклонены схемой до поиска из-за пропущенного обязательного `objective`. Итого запрошено 45 с учётом этих попыток; успешно выполненные поиски запрашивали 30.

Полные HTML лежали только во временном `/tmp/qala-2gis-research`, а не в репозитории или архиве. Из них можно повторно выполнить ограниченный парсер без сети:

```bash
.venv/bin/python -m scripts.providers.two_gis \
  --html /tmp/qala-2gis-research/1.body \
  --url https://2gis.kz/astana/firm/70000001018608940 \
  --observed-at 2026-10-20T15:57:45.557163+00:00 \
  --out /tmp/qala-2gis-museum.json
.venv/bin/python -m pytest backend/tests/test_two_gis_provider.py -q
```

Значение `--observed-at` нужно взять из исходного `http-evidence.json` для этого ответа: это время получения страницы, а не текущего повторного разбора. CLI требует исходную дату ISO 8601 с часовым поясом. Если при программном вызове `parse_html(..., observed_at=...)` время не передано, `observed_at` остаётся `None` с явным предупреждением; повторный разбор не делает старый снимок свежим.

Парсер `scripts/providers/two_gis.py` не делает HTTP-запросов. Он проверяет точный домен и путь фирмы, согласованность H1 с OG, диапазон балла и координат, раздельные счётчики, CAPTCHA и принадлежность обложки фирме. Индексы филиалов и поисковые выдачи не превращаются в единую оценку бренда. После проверки временных меток девять тестов проходят без внешних сервисов; исходный отчёт сбора сохраняет исторический результат шести тестов. Повторное чтение HTML не задаёт новую дату наблюдения: нужно передать исходное `observed_at`, а CLI требует его с часовым поясом.

## Что даёт официальный API

В [Places API](https://docs.2gis.com/en/api/search/places/overview) документированы поиск организаций/геообъектов, ограничения по городу/координатам, часы работы и дополнительные платные поля. [Схема `/3.0/items`](https://docs.2gis.com/en/api/search/places/reference/3.0/items) содержит `items.point`, `items.reviews` и статистические поля `rating`, `review_count`, `general_*`, `org_*`. Это не тело пользовательских отзывов и не лицензия на экспорт.

Есть существенная неоднозначность документации: [инструкция фильтрации](https://docs.2gis.com/en/api/search/places/examples/filtering) говорит, что `has_photos`, `has_reviews`, `has_rating` позволяют фильтровать по наличию, но получение фотографий, отзывов и значения рейтинга не поддерживается; при этом схема перечисляет статистику. Без собственного ключа и подтверждения доступных полей нельзя утверждать, какие именно показатели доступны подписке.

Реально отправлен запрос без ключа: `GET https://catalog.api.2gis.com/3.0/items?q=cafe&location=71.43045,51.12829&fields=items.point,items.reviews`. HTTP-ответ — **200**, но `meta.code=400`, ошибка поля `key`. Это отказ API, а не успешное получение мест. Доступ [создаётся в Platform Manager](https://docs.2gis.com/en/platform-manager/subscription/keys): демо-ключ после входа либо ключ подписки. Чужие ключи из фронтенда 2GIS не использовались.

## Условия и доступные способы интеграции

Первичный [лицензионный договор Казахстана](https://law.2gis.kz/licensing-agreement/ru), раздел 6.1.2–6.1.6, ограничивает создание производных информационных продуктов и отдельное использование извлечённой базы. [Правила API](https://law.2gis.kz/api-rules/ru), разделы 5.1–5.2, описывают ограничения использования и хранения полученных продуктов. Это препятствие массовому зеркалированию в распространяемый датасет даже при доступном HTML. Сами технические наблюдения не подтверждают договорную возможность перепубликации. Для масштабного приложения нужен согласованный с 2GIS режим и права на конкретные данные; сохранение фотографий/отзывов не следует считать автоматически разрешённым после получения ключа.

Официальные [микросайты](https://help.2gis.ru/question/microsites) могут показывать фотографии и отзывы **собственной организации**, управляются из её личного кабинета и связаны с рекламным размещением; отзывы там отбираются начиная с четырёх звёзд. Это не универсальный API всех отзывов Астаны и не нейтральная выборка для ранжирования. [Конструктор карты](https://help.2gis.ru/question/konstruktor-kart-instrukciya) позволяет встраивание карты, но текущий выбор пользователя — MapLibre; рендерер приложения не менялся.

## Практический результат для Qala

Есть работающий парсер фактических публичных метаданных, два реальных контрольных объекта, точные ссылки на их галереи/отзывы, обнаруженные ошибки свежести и подтверждённые границы доступа. Нет утверждения о полном обходе Астаны, лицензированном наборе фотографий или разрешённой базе отзывов 2GIS. До согласования прав эти записи остаются отдельным исследовательским слоем и не меняют RAG, публичные выгрузки или оценки существующих мест.
