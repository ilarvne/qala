# Yandex native map implementation

Checked against the current official v3 documentation and the official `@yandex/ymaps3-types@1.0.21651608` declaration package on 19 October 2026. The application loads the maintained provider-hosted `/v3/` runtime. Installing a type declaration package does not pin that runtime.

The native component is `src/components/YandexMap.tsx`; `src/lib/yandex-loader.ts` owns the shared bounded SDK load. A project-owned JavaScript API key is required. No provider example key was copied. Without that key, this code's authenticated landmark rendering remains unverified in Qala.

## Implemented API contract

- [Connection and readiness](https://yandex.com/maps-api/docs/js-api/quickstart.html): load `https://api-maps.yandex.ru/v3/?apikey=…&lang=…`, then await `ymaps3.ready`. HTTP Referer restrictions are required and initial key activation may take up to 15 minutes. The loader permits 15 seconds for script plus readiness, removes failed scripts, clears rejected shared loads for retry, and keeps key values out of its own errors.
- [Native map lifecycle](https://yandex.com/maps-api/docs/js-api/map/YMap.html): construct `YMap(container, props)`, attach entities with `addChild`, detach with `removeChild`, and call `destroy()` on unmount. The SDK observes the map container size itself. Map margins are `[top, right, bottom, left]` in pixels.
- [Camera](https://yandex.com/maps-api/docs/js-api/examples/cases/camera.html): tilt and azimuth use radians; durations use milliseconds. The initial camera uses 45° tilt and −18° azimuth. Camera requests retarget from current public getters. Keyboard actions and reduced-motion preference use zero duration.
- [Actual 2D](https://yandex.com/maps-api/docs/js-api/examples/cases/customization.html): the documented customization object `{"style":[], "render-3d":"off"}` disables vertical map geometry. Switching to 2D also resets tilt and azimuth and removes tilt/rotation gestures. Returning to 3D replaces customization with `{style:[]}` and restores those gestures. Camera pitch alone is insufficient.
- [Route geometry](https://yandex.com/maps-api/docs/js-api/object/geo-objects/YMapFeature.html): an independent Valhalla `LineString` is supplied directly to `YMapFeature` under a `YMapDefaultFeaturesLayer`. No Yandex routing call replaces it. The [stroke example](https://yandex.com/maps-api/docs/js-api/examples/cases/stroked-line.html) supports layered strokes; Qala uses blue route plus white casing and `simplificationRate:0`.
- [Markers](https://yandex.com/maps-api/docs/js-api/object/markers/YMapMarker.html): native `YMapMarker` attaches the application's real numbered HTML buttons to coordinates. Selection updates `aria-pressed`, marker z-index, name label and camera target. GPS and origin are separate marker entities. Place buttons support normal browser keyboard activation and block map gesture/event propagation.
- [Loading state](https://yandex.com/maps-api/docs/js-api/object/events/YMapListener.html): `onStateChanged` exposes `state.getLayerState(YMapDefaultSchemeLayer.defaultProps.source + ':ground', 'tile', 'vector')`. At least one ready ground tile establishes basic map availability. This does **not** establish completion of detailed landmark assets. The complete initial connection has a 20-second recovery bound; WebGL context loss also exposes recovery.
- [Locales](https://yandex.com/maps-api/docs/js-api/map/localization.html): the current documented list lacks Kazakh. The loader uses `en_RU` for initial English and `ru_RU` for Russian/Kazakh, both metric. Provider labels retain the SDK's initially loaded language within a page session; Qala's own controls and marker labels update with application language.

The native renderer reserves the measured itinerary area below its viewport. Provider copyrights and distribution controls remain inside that visible renderer, rather than depending on private DOM selectors to move every provider control. Native camera margin adds only 24 pixels at the bottom of that already reserved viewport. The current default feature layer z-index is deliberately above the scheme so the independent walking line remains legible. The final authenticated layout still requires inspection with the project's own key.

## Scope of verification

Type checking and a local mocked native-SDK contract can verify supplied geometry, selection, true-2D requests, camera units, reduced motion, recovery and disposal. Those checks cannot prove provider coverage, successful project-key access, attribution layout or hardware performance. Those require a project-owned key and the actual production renderer.

The isolated real-component contract passed 17 checks. A separate actual browser focus/Enter check selected the numbered alem.ai marker, updated its pressed state and label, and requested a zero-duration camera move. An actual provider-script request with a deliberately invalid synthetic key exposed recovery, removed the rejected script, retried through a second attempt, left zero canvases, and produced no unhandled page errors. [Recorded results](../../artifacts/yandex-native-contract-verification.json).

The official provider-hosted SDK example was also used to verify the actual native `YMapFeature`, `YMapDefaultFeaturesLayer` and DOM-marker primitives without moving its key into Qala. The native blue-4-pixel/white-8-pixel stroke array visibly produces a blue route with white casing; [the retained screenshot](../../artifacts/screenshots/yandex-native-sdk-stroke-proof.png) shows that exact supplied line. This is an SDK primitive check, not an authenticated Qala coverage test. Its attribution DOM class is `ymaps3--map-copyrights ymaps3--map-copyrights_bottom ymaps3--map-copyrights_right`. The example had no distribution element, so that element's project-key layout remains to be checked.

The applicable Kazakhstan terms restrict free real-time monitoring. Personal navigation and the account's permitted usage should be resolved through the provider or applicable commercial terms before claiming that the entire GPS flow qualifies for free use.
